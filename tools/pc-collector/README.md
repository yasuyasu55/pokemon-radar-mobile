# PC収集・モバイル結果閲覧

## まず1回確認する（Windows実機未確認）

リポジトリ直下の START-PC-COLLECTION.cmd をWindows PCで起動します。専用フォルダを自動で用意します。既存のPC版v0.7.0や、その自動起動設定には触れません。

必要なものは Node.js 22以上、Git、GitHub CLI、本人のGitHubログインです。不足している場合は収集を始めず、pc-check.txtを表示します。ソフトの自動インストールや認証情報のファイル保存はしません。

準備が揃っていれば、必要なPlaywrightブラウザを用意し、Amazon・楽天を確認します。Amazonは画面の見える通常ブラウザを使用します。既存Chromeのログイン情報は取り込みません。ブラウザ設定の偽装、CAPTCHA回避、購入、招待リクエストのクリックはしません。アクセス確認画面や拒否が出れば停止します。PCへ変えただけで取得成功するとは保証できません。

## 結果の確認

結果は %LOCALAPPDATA%\\PokemonRadarCollector\\last-result.json に保存します。セットアップ前の不足項目は同じフォルダの pc-check.txt に保存します。このファイルを開発担当へ渡すと、取得と公開のどこで停止したか確認できます。

- amazon: 詳細確認件数、2回一致件数、新規公開件数、ACCESS_BLOCKED等
- rakuten: 独立2回の照合結果
- changedCases: 新規IDか、既存案件の再確認か
- publication: SENT_NOT_CONFIRMED は送信のみ。PUBLIC_RESULTS_CONFIRMED は公開URLで変更対象の反映まで確認
- errors: 未完了の工程

公開URLの確認は最大5回です。確認できない場合は成功扱いにしません。生HTML・Cookie・GitHubトークンは結果ファイルへ保存しません。

## 運用

PCの収集はJST日付ごとに1回だけ試行します。同日に再度起動しても再収集しません。失敗時も当日は自動再試行しません。2つ同時起動した場合にも同じ日付の予約を重複できないようにしています。

自動起動やタスク登録はありません。PC上の取得・公開が確認できた後、必要に応じて定期化する段階です。並行更新でpushが拒否されたら停止します。強制pushや自動競合解消はしません。

移行確認まではGitHub側の1日1回収集を維持しています。PC側の起動ファイルを用意したことと、PC運用の成功は別です。

スマホは結果閲覧のみです。開いた時と「結果を更新」を押した時だけ保存済み結果を取得し、待機中の定期通信・再描画はありません。応募済み・お気に入り・LINE共有は利用できます。

## 開発側の検証

日付境界、別プロセスの同時起動、古い公開データを誤って反映成功にしないこと、独立2回の厳格確認、アクセス拒否時の停止をテストしています。Windows PC・実Amazon・実公開の一連動作はユーザーPCでの確認待ちです。
