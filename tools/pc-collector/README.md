# PC収集・モバイル結果閲覧

スマホは保存済み結果を最初の表示時と「結果を更新」操作時だけ取得します。30秒の定期再描画、5分の定期取得、画面復帰時の自動取得はありません。応募済み・お気に入り・絞り込み・LINE共有は従来どおり利用できます。公式サイトを開いた後の動作は販売元のサイトによります。

## PC収集（Windows実機確認待ち）

Node.js 22以上、Git、GitHub CLIを利用します。GitHub CLIはリポジトリへ書き込める本人のアカウントで `gh auth login` を済ませてください。無料で使う構成です。

初回は専用フォルダで `git clone https://github.com/yasuyasu55/pokemon-radar-mobile.git` を実行します。既存のPCアプリv0.7.0へ上書きしないでください。

クローンしたフォルダの `tools/pc-collector/RUN-PC-COLLECTOR.cmd` を起動すると、Amazonと楽天ブックスの既存収集・独立2回検証・公開データ送信を順に実行します。Amazonでアクセス拒否が出たら既存ルールで停止し、楽天は継続します。CAPTCHA回避、購入、招待リクエストのクリックは行いません。通常のPlaywrightブラウザを使用し、ログイン済みChromeを引き継ぎません。PCに変えただけでAmazonの取得成功を保証するものではありません。

送信後はGitHub Pagesの配信完了を待ち、スマホの「結果を更新」を押します。PCを切っている間も前回の結果は閲覧できます。

自動起動・スケジュール登録はしません。Windowsでの動作と公開結果を確認した後に定期化する段階です。並行更新によりpushが拒否されたら停止します。強制pushはしないでください。証跡は画面に表示した一時フォルダへ保存します。

## 移行状態

この追加だけではWindows側は起動していません。既存のGitHub定期収集は移行確認まで維持しています（GitHubで動く処理はiPhoneでは実行されません）。PC側でAmazon・楽天の収集、公開反映を確認後、その2本の定期実行をPCへ移します。他店舗とXの収集経路の移行も別途確認が必要です。スマホの軽量化とPCへの全収集移管を同じ完了状態として扱わないでください。

別アプリの終了や充電速度との因果関係は未確認です。今回の変更はブラウザの待機中処理を減らすものです。
